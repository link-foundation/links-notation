### Added

- Keep how references were written. A link read by the parser records its ID
  exactly as written (`rawId`: `'1'`, `1`, `""a b""`, `~1{31}`) and the quote
  it was written between (`quote`), so `(t 1 '1')` can be told apart from
  `(t 1 1)` after `parse()` and `parseGroups()`. The metadata is on by default
  and is ignored by equality, hashing and formatting: `1` and `'1'` stay the
  same reference and `(t 1 '1')` still formats as `(t 1 1)`. An AST mode leaves
  it out.
- Add a lossless concrete syntax tree (`parseCst`): every character of a
  document, comments, whitespace, blank lines, line endings and quote runs
  included, belongs to exactly one token, so the tree's text is the document.
- Implement both in all eight bindings (JavaScript, Rust, Python, Java, Go, C#,
  PHP and C++), checked against shared golden data in
  `parity/syntax-fixtures.json` and `parity/syntax-vectors.tsv`, with a
  round-trip test over every shared text and syntax fixture in every binding.

### Changed

- Prepare version 0.28.0 across all eight bindings.

### Fixed

- Python, Go, PHP and Java no longer read a bare reference past a space
  because it contains a quote character: `('x y)` now reads the two references
  `'x` and `y`, as JavaScript, Rust, C# and C++ always did.
