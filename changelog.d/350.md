### Fixed

- Merge Dependabot's minor and patch pull requests once their checks pass.
  `AutoMerge.yml` ran `gh pr merge --auto`, which failed on every pull request
  because the repository does not allow auto-merge and Dependabot-triggered
  runs never receive the `DEPENDABOT_AUTO_MERGE_TOKEN` Actions secret. It now
  runs `scripts/ci/merge-dependabot.py` after the pull request workflows finish
  and every six hours. The script merges only pull requests with Dependabot's
  own commits whose checks all passed, pinned to the checked head commit. Since
  `main` requires up-to-date branches, it also brings one behind pull request
  up to date per run.
- Fail the dependency freshness check on a pull request only for the
  declarations that pull request adds or changes
  (`check-dependencies.py --changed-since`). Every other outdated package is
  printed as a note, and stale transitive npm entries are reported without
  failing. Before, every single-package bump failed while any other package
  was behind. Push and scheduled runs on `main` still check everything, and
  their failures now say how to fix them.
- Create the `python`, `rust`, `csharp`, `java`, `php` and `go` labels that
  `.github/dependabot.yml` applies, and use the existing `github_actions` label
  for GitHub Actions updates. CI now fails when a configured label is missing.
- Update `pypa/gh-action-pypi-publish` to v1.14.3 for GHSA-5xjx-3w67-w9x9.
